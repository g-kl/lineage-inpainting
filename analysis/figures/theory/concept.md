# concept

The figures behind the theory supplement (S4): why the alignment loss compares
low-order feature laws rather than whole trees, and what that choice costs.
Four renders, one exact and three about finite samples, all on binary states
so that every population quantity can be computed exactly.

- **Ising running example** (`imgs/ising_running_example.pdf`, two pages) --
  the theory supplement's figure. Page one tells the binary-table story on a fork and on the
  seven-node (depth-two) binary tree: the independent fork law against the
  Bernstein triple, the path and common-ancestor tables, and the compatible set
  of whole-tree laws that share all four size-three tables. Page two is the
  dependence--risk decomposition along the edge-correlation family `P_rho`:
  squared worst-case discrepancy, feature sampling variance, and their sum
  against the whole-tree MSE, first at equal tree counts and then at equal
  representation budgets.
- **Bernstein feature-law figure** (`imgs/bernstein_figure.*`) -- the exact
  depth-three (15-node) construction: the Bernstein product and its two
  balanced-tree placements, the all-times-feature MSE decomposition, and the
  omission/attenuation matrices across feature order. The seven-node example
  is a reduction of this construction.
- **Parity benchmark** (`imgs/bernstein_parity*.*`) -- empirical: the real
  `StratifiedFeatureAligner` scoring exact parity laws on a lollipop tree, to
  show which feature orders and placements reveal an order-`r` parity.
- **Efficiency benchmark** (`imgs/bernstein_efficiency.*`) -- empirical: how
  many independent trees a null-calibrated energy test needs as the feature
  order grows past the parity, energy against exact `W_1` on the same feature
  samples, and wall-clock scaling of the two discrepancies. This is the
  empirical evidence that variance grows with feature order.

## the seven-node example

`depth2.py` holds the calculation. The tree has a root, two children and four
grandchildren; states are signs. Child-order symmetry groups the 128 sign
assignments into 42 orbits, and the energy distance on binary vectors is
diagonal in the Walsh basis with weights `gamma_weight`. The four size-three
feature tables (one path table over levels 0-1-2 and three common-ancestor
tables over the level pairs) span 13 of the 41 probability directions, so the
compatible set of a reference law is a 28-dimensional polytope. For each rho
in the family `P_rho` (fair root sign, parent sign kept with probability rho),
`compute_depth2.py` searches that polytope for the compatible law `Q_rho`
farthest from `P_rho` in whole-tree energy: SCIP through `pyscipopt` by
default, or `--search` for a multi-start local search on scipy alone. The
U-statistic variances of both statistics are exact (`u_variance`), and the
equal-budget panels charge the whole-tree statistic one representation per
distinct child ordering.

The solutions are slow to certify and SCIP is not installed everywhere, so the
certified file `depth2_identification_results.json` is committed next to the
module and `plot_ising.py` reads it. A fresh solve lands in
`numerical_results/`; check it with `--render` (the two diagnostic panels of
`plot_depth2.py`) and copy it over the committed file by hand.

## the depth-three construction

The calculation uses the same balanced binary tree and time strata as the
running Ising example. The tree has depth three and 15 binary states. For
orders `r = 2, 3, 4`, a depth interaction occupies the last `r` nodes of a
root-to-leaf path. There are eight such supports at every order. A breadth
interaction occupies one level-one ancestor and `r - 1` of its four
level-three descendants. Summing over both level-one ancestors gives
`M_r = 8, 12, 8` supports at orders two, three, and four.

The law is the uniform reference tilted by the average parity over the aligned
support family. Its Walsh-moment gap is therefore `theta / M_r` on every
support and zero elsewhere. The averaging is essential: the code checks that
each support family is invariant under all 128 automorphisms generated by
local child exchanges. It also enumerates all 32,768 assignments and verifies
the complete Walsh moment vector of every law. The breadth family at a fixed
order can contain more than one tree-automorphism orbit; uniform averaging
over all aligned supports is the pooled construction matched by the feature.

A path feature of order `q` pools the last `q` nodes of all eight
root-to-leaf paths. A common-ancestor feature pools a level-one ancestor with
ordered samples of `q - 1` among its four level-three descendants. Thus a
matched `q >= r` path feature contains one nonzero relative order-`r` row. A
matched common-ancestor feature contains `L_qr = choose(q - 1, r - 1)` such
rows. Each row has gap `theta / M_r`, so after removing the Walsh weights the
raw feature-to-whole discrepancy ratio is `1 / M_r` for the path and
`L_qr / M_r` for the common ancestor. Whitening duplicate pooled rows in the
full-tree energy geometry gives a canonical visible ratio of one whenever
`q >= r` and zero otherwise. This separates detection of the aligned
population direction from the raw loss calibration.

The finite-sample panels compare the complete tree with the full order-three
operator used in the sister Ising figure: one path law spanning levels
`(1,2,3)` and separate common-ancestor laws for time pairs `(1,2)`, `(1,3)`,
and `(2,3)`. The aligned breadth interaction has order four, so every feature
mean remains zero. Here `M_4 = 8`, the normalized full-tree discrepancy is
`theta^2 / 8`, and the feature discrepancy is zero. The plotted variance is
that of the unbiased tree-level two-sample U-statistic. The full-tree feature
has 32,767 rows, so its three variance coefficients are obtained from the
sparse parity moments and one exact Walsh--Hadamard autocorrelation. No
simulation or fitted quantity enters the figure.

The final panels display the raw coefficient directly as two `r`-by-`q`
matrices. Every entry with `q < r` is zero, while a positive entry gives the
raw feature loss divided by the aligned whole-tree loss. The path coefficient
is `1/8` throughout the detected region; common-ancestor pooling increases it
from `1/12` to `3/8` as the feature contains more order-`r` blocks. Placement
sampling is absent from these matrices because it changes variance, not the
population coefficient.

## the two benchmarks

Both use the standard order-`K` parity: `K - 1` independent Rademachers and a
final coordinate equal to their product, so every strict subset is independent
while the full tuple is not.

The parity benchmark builds one shared order-6 lollipop tree (a chain of six
nodes with five leaves hanging off the last one), embeds an order-`r` parity
either along the chain or across the terminal node and a random `r - 1` of its
children, and scores feature order `q` against parity order `r` with the
`PathFeature` and `CommonAncestorFeature` of the aligner, energy distance,
4096 trees per population and 32 replicates. The excess over the independent
null floor is invisible for `q < r` and appears once the feature contains the
full tuple. The trajectory panel draws the null, the chain parity and the fan
parity as lollipop clouds.

The efficiency benchmark keeps an order-3 chain parity fixed and appends
independent nuisance states to raise the feature order. Its three panels are
the detection probability of a null-calibrated (5%) energy test against the
number of independent trees, energy excess against exact assignment-`W_1`
excess on identical feature samples across parity mixtures, and the median
wall time of a fixed-reference energy update against an exact `W_1` solve as
the sample count grows.

# implementation

Compute is split from plotting. `compute_*.py` write into `numerical_results/`
and `plot_*.py` plus `assemble.py` read only from there and write into
`imgs/`; both directories are gitignored and regenerable. The one exception is
`depth2_identification_results.json`, the certified solver output described
above, which is committed. `style.py` holds the shared paths, page geometry,
fonts (Latin Modern Sans from `utils/figure_labels`) and palette; the two
benchmarks keep the `synthetic_evals.viz` look they share with the synthetic
figures.

- `exact.py` -- the depth-three calculations; `depth2.py` -- the seven-node
  calculations and solver.
- `compute_bernstein.py` -> `attenuation_exact.csv`, `cell_phase_exact.csv`,
  `diagnostics.json`. Exact, a few seconds.
- `plot_concept.py`, `plot_phase.py`, `plot_attenuation.py` -> `imgs/panels/`;
  `assemble.py` regenerates all three and nests them into
  `imgs/bernstein_figure.{svg,pdf,png}` (`rsvg-convert` and `gs`; the PDF is
  downgraded to 1.5 for pdfTeX).
- `compute_depth2.py` -> `depth2_identification_results.json` (SCIP or
  `--search`); `plot_depth2.py` -> the two diagnostic panels; `plot_ising.py` ->
  `imgs/ising_running_example.pdf` (needs `gs`).
- `compute_parity.py` -> `parity_raw.csv`, `parity_summary.csv`,
  `parity_config.json` and a pickle cache; `plot_parity.py` -> the three
  parity renders. The full grid is long on a CPU; `--quick` (256 trees, two
  replicates) smoke-tests the pipeline and writes under `numerical_results/quick/`
  and `imgs/quick/`.
- `compute_efficiency.py` -> the power, scatter and timing CSVs plus a cache
  keyed by the numerical configuration; `plot_efficiency.py` -> `imgs/bernstein_efficiency.*`.
  Same `--quick` convention.

## run order

From the repository root, in an environment with Python 3.10+, torch and
seaborn (the benchmarks import the aligner and the shared palettes; the exact
figures need only numpy, scipy and matplotlib):

    python -m analysis.figures.theory.compute_bernstein
    python -m analysis.figures.theory.assemble
    python -m analysis.figures.theory.plot_ising
    python -m analysis.figures.theory.compute_parity        # long; --quick to smoke-test
    python -m analysis.figures.theory.plot_parity
    python -m analysis.figures.theory.compute_efficiency    # cached after the first run
    python -m analysis.figures.theory.plot_efficiency

`compute_depth2.py` is only needed to re-certify the seven-node solutions.
